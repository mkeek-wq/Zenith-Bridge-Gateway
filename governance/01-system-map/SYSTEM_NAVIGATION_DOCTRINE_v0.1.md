# ZNBW System Navigation Doctrine v0.1

**Date:** 07 Jul 2026
**Status:** Active doctrine
**Purpose:** Ensure any future human, AI, or developer can open the system documentation and understand what exists, where it lives, how it connects, and what maturity level it has.

---

# 1. Core Principle

ZNBW has reached a scale where memory is no longer enough.

The system must be navigable through documentation, generated registries, and clear paths.

A future human, AI, or developer should be able to open the system map and understand:

1. What exists
2. Where it lives
3. What it depends on
4. What consumes it
5. How mature it is
6. Whether it is safe to run
7. What should happen next

---

# 2. Documentation Doctrine

No major engine, registry, pipeline, package, dashboard, or client-facing product surface is considered complete until it is documented with:

- Purpose
- Repository path
- Runtime path, if applicable
- Input packages
- Output packages
- Consumers
- Product surface
- Maturity level
- Quality / audit status
- Known risks
- Recommended next action
