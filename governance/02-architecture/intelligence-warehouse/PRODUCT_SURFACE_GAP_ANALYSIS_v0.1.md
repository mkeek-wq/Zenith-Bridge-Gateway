# Product Surface Gap Analysis v0.1

**Date:** 06 Jul 2026
**Status:** Discovery
**Purpose:** Identify intelligence capabilities that already exist but are not yet visible as admin, dashboard, article, or client-facing product surfaces.

---

# 1. Summary

ZNBW already contains multiple functioning intelligence chains.

The main product gap is not engine creation.

The main product gap is surfacing.

```text
Existing intelligence
↓
Hidden packages
↓
Limited admin visibility
↓
No client-facing product surface
```

# 4. Product Surface Candidates

| Candidate Surface | Source Intelligence | Value | Difficulty | Priority |
|-------------------|--------------------|-------|------------|----------|
| Replay Dashboard | Replay Support / Case Construction / Outcome Attribution | High | Medium | High |
| Forecast Dashboard | Forecast Envelope / Confidence / Historian | High | Medium | High |
| Decision Dashboard | Decision Support / Case Construction | Very High | Medium | High |
| Macro Dashboard | Macro Attribution / Diversity / Concentration | Medium-High | Low-Medium | Medium |
| Intelligence Warehouse UI | Engine/package registries | High internal value | Medium | High |
| Client Portal Surface | All orchestrated outputs | Very High | High | Later |

---

# 5. Recommended Sequencing

```text
1. Intelligence Warehouse UI
2. Replay Dashboard
3. Forecast Dashboard
4. Decision Dashboard
5. Client Portal integration
```

Rationale:

```text
The Intelligence Warehouse UI should come first because it helps Papa understand what exists.

Replay, Forecast, and Decision dashboards should follow because they convert hidden intelligence into product surfaces.

Client Portal integration should wait until internal surfaces are understandable and stable.
```

---

# 6. Conclusion

```text
ZNBW is not missing intelligence.

ZNBW is missing product surfaces.

The next product-building phase should focus on surfacing:

- replay
- forecast
- decision
- macro
- warehouse visibility
```
